## 1. 概述

**一句话：任何网站加一行代码，用户就能用说的完成任务。**

Voilà Button 是一个嵌入商家网站的语音按钮。用户按住按钮说出需求，后端调用 H Company 的 computer-use agent，在该网站上替用户点击、填写、付款；付款等不可逆操作前，agent 会口头读回摘要并等待用户确认。

## 2. 背景与问题

- 视障/低视力、老年、运动障碍、以及不懂站点语言的用户，在现有网站上完成下单、预约、缴费非常困难：屏幕阅读器需要逐个听几百个元素，外语用户根本看不懂表单。
- 欧洲无障碍法案（EAA，2025-06 生效）使电商、银行、交通、药房等行业开始为"无障碍"设立预算、寻找供应商。
- EAA 覆盖的站点数量级是百万，完成整改需要很多年，而用户今天就需要完成任务。
- Computer-use agent 第一次做到"看屏幕就能操作任何网站"；H 的 Agents API 将其做成可按次调用、可观测、可中途干预的云服务。

## 3. 定位

**我们说"无障碍"，不说"合规"。**

- Voilà 提供的是**替代完成路径**：让无法使用键盘/看不见屏幕/不懂法语的用户也能完成任务。
- Voilà **不改变网站本身**：缺失 alt、键盘不可达、表单缺 label 等问题依然存在，WCAG / EN 301 549 审计结果不会改变。
- 不得宣称"装了就合规"（overlay 厂商如 accessiBe 曾因此被起诉）——这是产品与营销的红线。
- 卖点是**结果指标**：残障/老年/外语用户的任务完成率、购物车放弃率、客服电话量。
- 标准对外表述："Voilà 让每一位用户都能完成任务；它是无障碍整改的补充，不是替代。"

## 4. 目标与非目标

### 4.1 目标

1. 用户无需看屏幕、无需安装任何东西，仅靠语音即可在商家网站上完成一次完整交易（含付款）。
2. 商家接入成本极低：一行 `<script>` + 一段自然语言站点说明。
3. 不可逆操作（付款）100% 经过用户口头确认。
4. 全程透明：进度实时朗读，可查看实时画面与事后回放。
5. 用户语言与网站语言解耦。

### 4.2 非目标

- 不修复网站本身的无障碍缺陷，不出具合规证明。
- 不替代屏幕阅读器等辅助技术。
- MVP 阶段不解决验证码；不接入真实支付（仅 Stripe 测试模式）。
- MVP 阶段不做模式 C（页面内原生执行），仅做 PoC。

## 5. 用户与客户

| 角色 | 说明 | 是否付费 |
| - | - | - |
| 商家（买家） | 电商、药房、银行、交通等受 EAA 影响的网站方 | 是：按月订阅 + 按任务计费 |
| 终端用户 | 视障/低视力、老年、运动障碍、不懂站点语言的人 | 否，不安装任何东西 |
| 照护者/家属 | 事后查看用户代办记录 | 否 |

## 7. 产品形态与架构

```
商家网页 ──<script src="voila.js">──► Voilà 按钮（麦克风 + 进度朗读 + 实时画面）
                                            │  音频流
                                            ▼
                                   Voilà 后端（Node/Python）
            ┌──────────────┬──────────────┼──────────────┬──────────────┐
            ▼              ▼              ▼              ▼              ▼
         Gladia         Linkup        H Agents API    Stripe        用户档案
       实时 STT +      快速问答        云端浏览器      Payment/     （姓名、地址、
       语种检测        （带来源）      执行任务        Checkout      常用项）
```

### 7.1 运行模式

| 模式 | 实现 | 实测（12 步下单） | 优先级 |
| - | - | - | - |
| A. 云端浏览器 | `host: cloud`；`LiveViewUrlEvent` 将实时画面嵌回按钮 | 启动 8–9 s，每步约 3 s，全程 40–59 s，$0.03–0.04 | **P0 主模式** |
| B. 用户自己的浏览器 | `Client.local()` + `host: user_device`（HoloTab 扩展或桌面 runtime） | 启动 3 s，每步约 2 s，全程 27 s | P1（需要登录态的场景；demo 热备） |
| C. 页面内原生 | 按钮截图 → Models API `element-localization` 拿坐标 → JS 触发点击 | 单次定位 0.15–0.4 s，6/6 命中 | P2（v2；周末仅 PoC） |

## 8. 功能需求

优先级：P0 = MVP 必须；P1 = MVP 应有；P2 = 后续版本。

### 8.1 按钮前端（voila.js）

| ID | 需求 | 优先级 |
| - | - | - |
| FR-1 | 通过一行 `<script>` 注入，在页面右下角显示大尺寸圆形按钮 | P0 |
| FR-2 | 按住说话，音频流实时发送至后端（Gladia WebSocket），并在按钮上显示转写文本 | P0 |
| FR-3 | 通过 TTS 播放进度、确认问题与最终结果 | P0 |
| FR-4 | 内嵌 agent 实时画面（`live_view_url` iframe）；若该事件不可用，则降级为 Agent View 链接 | P1 |
| FR-5 | 监听"停"等指令，触发暂停/取消 | P1 |
| FR-6 | 按钮本身满足键盘可达、屏幕阅读器可读 | P0 |

### 8.2 后端编排

| ID | 需求 | 优先级 |
| - | - | - |
| FR-10 | 意图路由：只读问答走 Linkup（带来源），任务类请求走 H Agents API | P0 |
| FR-11 | 将用户档案（姓名、电话、地址、常用项）与站点说明拼入 task 文本 / `instructions` | P0 |
| FR-12 | 流式读取 `changes`，提取 `policy_event.content` 送 TTS 朗读 | P0 |
| FR-13 | 自定义工具 `confirm_with_user(summary)`：TTS 读出 agent 生成的摘要，Gladia 识别"oui/non/确认/取消"，结果返回 agent | P0 |
| FR-14 | 中途干预：`POST /sessions/{id}/pause`、`DELETE`（取消）、`send_message`（纠正） | P1 |
| FR-15 | 使用 `answer_format` JSON schema 获取结构化结果 `{ref, total, items}`，用于朗读和回执短信 | P1 |
| FR-16 | 银行卡通过 H vault + `fill_secret_at` 填写，卡号不进入模型上下文 | P1 |
| FR-17 | 多语种：Gladia 检测语种，任务与朗读使用用户语言，与网站语言无关 | P1 |
| FR-18 | 审计回放：保存每步 `observation_event.image` 截图与 Agent View 链接 | P1 |

### 8.3 商家接入

| ID | 需求 | 优先级 |
| - | - | - |
| FR-20 | 一行 `<script>` 接入 | P0 |
| FR-21 | 站点说明（Site Skill）：自然语言描述关键页面、控件与下拉选项全文 | P0 |
| FR-22 | 可配置 `start_url`（直达目录页等） | P0 |
| FR-23 | 可配置可跳过步骤（如登录态）与禁止区域（如删除账户、修改密码） | P1 |
| FR-24 | 付款金额阈值上限，超过即拒绝或需额外确认 | P1 |

### 8.4 推荐 agent 配置

- 模型 `holo4-27b`，`reasoning_effort: disabled`，`settle_s: 0.3`，视觉模式 1280×800。
- 提供站点说明 + `start_url` 直达目录页（实测步数 13 → 11，耗时 50 s → 40 s）。
- `holo4-35b-a3b` 仅用于只读问答类任务（实测在首页卡片上乱点，省钱不省时）。
- `max_steps: 40`，`max_time_s: 300`。

## 9. 非功能需求

| 类别 | 要求 |
| - | - |
| 延迟 | 典型下单任务端到端 ≤ 60 s（目标 30–40 s）；问答 ≤ 5 s；每步均有朗读，无冷场 |
| 成本 | 单次下单 agent 成本 ≈ $0.03–0.04；含 STT/TTS 每任务 < €0.10 |
| 可靠性 | Demo 场景二连续 3 次 ≤ 60 s 成功 |
| 安全 | 不可逆操作强制确认；卡号走 vault；禁区由商家配置 |
| 隐私 | 截图保留期可配置（`delete_after_min`）；模式 B/C 截图不离开用户机器 |
| 无障碍 | 按钮自身符合 WCAG 2.2 AA |
| 并发 | 免费版全 org 仅 3 个并发 session；生产需 Builder（10 并发）或更高 |

## 10. 成功指标

**产品指标（面向商家）**
- 目标用户群的任务完成率
- 购物车放弃率下降
- 客服电话量下降
- 单任务成本与单任务时长

**MVP / Demo 验收**
- 场景一（问答）：语音提问 → 带来源回答朗读。
- 场景二（下单 + 付款）：≤ 60 s，付款前确认被调用，Stripe 回执送达。
- 场景三（多语种）：中文/阿拉伯语指令在法语站上完成并用母语朗读。

## 11. 实测基线（2026-11-07，仿真药房站）

任务：2 盒 Doliprane 到店取、填表、确认、付款。

| 配置 | 耗时 | 观察步数 | 成本 | 备注 |
| - | - | - | - | - |
| holo4-27b 默认（有 reasoning） | 58.8 s | 13 | $0.038 | 首页误点一次 |
| holo4-35b-a3b, reasoning off, settle 0.3 | 55.6 s | 17 | $0.032 | 首页卡片连点 4 次 |
| holo4-27b, reasoning off, settle 0.3 | 49.7 s | 13 | $0.039 | |
| 上一行 + 站点说明 + start_url=目录页 | **40.1 s** | 11 | **$0.030** | 推荐配置 |
| 同上，本地 runtime | **26.6 s** | 12 | $0.041 | 启动 3 s vs 9 s |
| Models API 单次元素定位 | 0.15–0.4 s | — | ~$0.0003 | 1280×800 截图 ≈ 1,130 tokens |

- `confirm_with_user`：4/4 次 agent 都在点付款前调用。
- 已知问题：原生 `<select>` 使用 `select_option` 必须给出**完整选项文字**（"Retrait en pharmacie (gratuit)"），应在站点说明中写明。

## 12. 商业模式

- B2B：按月订阅 + 按任务计费（建议 €0.2–0.5 / 任务）。
- 单位成本：agent 3–4 美分 + STT/TTS 几分钱，比一通客服电话便宜一个数量级。
- 护城河：每个商家一份站点说明（Site Skill）积累的数据。

## 13. 风险与对策

| 风险 | 对策 |
| - | - |
| 被视为 overlay 合规骗局 | 明确不替代整改，只谈任务完成；提供审计回放 |
| agent 误操作付款 | 强制 `confirm_with_user`；金额阈值；MVP 仅 Stripe 测试模式 |
| 延迟导致语音体验冷场 | 进度 TTS；站点说明减步数；`settle_s=0.3`；`start_url` 直达 |
| 真实站点有验证码/登录 | demo 用自建站；真实站用 vault/浏览器 profile 处理登录 |
| 截图上传的隐私问题 | 模式 B/C 本地处理；合同约定保留期（`delete_after_min`） |
| 小模型省钱但乱点 | 任务类固定用 holo4-27b |
| 并发配额不足 | demo 前确认无其他 session 运行，或升级 Builder |
| `LiveViewUrlEvent` 未触发 | 降级为 Agent View 页面 |

## 15. 待定问题

1. `LiveViewUrlEvent` 在云端模式下是否稳定触发？（周五晚验证）
2. H vault + `fill_secret_at` 与 Stripe Checkout 的配合方式（未测）。
3. 唤醒词"停"在 TTS 播放时的识别方案（回声消除 / 半双工）。
4. 用户档案的存储位置与授权方式（商家侧 vs Voilà 侧）。
5. 定价细节：按任务计费的分档与包月上限。
