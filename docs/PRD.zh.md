## 1. 概述

**一句话：城市交通瘫痪时，视障旅客说一句话，Voilà 帮他订到去机场的车，最后由他本人在自己手机上付款。**

Voilà 是一个手机语音助手。用户在嘈杂环境中说出需求后，Voilà 先实时核实情况，筛出仍然来得及的方案，并朗读给用户听。用户选定后，Voilà 调用 H Company 的 computer-use agent，到一个**从没为视障用户设计过的第三方网站**上完成预订。agent 走到付款步骤就停下，把商家自己的付款页交到用户手机上，由用户用 Apple Pay 支付。卡信息永远不会经过 Voilà 或 agent。

与 v0.1 的区别：v0.1 是商家嵌入自家网站的按钮（B2B，站点说明由商家提供）；v0.2 是**用户自己的语音助手**（黑客松阶段为手机网页），去操作没有接入任何东西的网站。详见[附录 B](#附录-b相对-v01-的变化)。

## 2. 主场景：RER B 停运

RER B 是巴黎市区去 CDG 机场唯一的铁路主干线，经常在几乎没有预警的情况下全线停运。

**设定。** Karim 是视障人士，带着导盲犬，正在巴黎北站（Gare du Nord）。他飞纽约的航班 3 小时后从 CDG 2E 航站楼起飞。车站警报和广播响个不停，他不知道为什么 B 线一直不来，Uber 也叫不到车。

| # | 发生了什么 | 技术 |
| - | - | - |
| 1 | **语音。** Karim 按住按钮急促地说："RER B 停了！我 3 小时后飞纽约的航班要来不及了！Uber 叫不到，立刻帮我订一辆现在能走、能带导盲犬去 CDG 2E 的车！" | Gladia 实时转写嘈杂语音 + 设备端降噪 |
| 2 | **理解。** 提取结构化行程：起点北站（GPS），终点 CDG 2E，航班起飞时间（未知则追问），1 名成人 + 导盲犬，行李。用户已排除 Uber。 | LLM + 用户档案 |
| 3 | **调研。** 屏幕上滚动数据流："RER B：交通中断（来源）……可行方案：北站出租车站、G7 预约、Paris Airport Shuttle……"。Voilà 朗读前 2–3 个方案的接车时间、价格、能否带导盲犬。 | IDFM PRIM 实时交通 API、Linkup 搜索（带来源）、可行性筛选 |
| 4 | **决策。** Karim："订接送车。" | 语音选择 |
| 5 | **执行。** H 云端 agent 打开 `paris-airport-shuttle.com/fr/reservation/`。这个预订表单对屏幕阅读器极不友好（见[附录 A](#附录-a真实站点观察)）。agent 依次填写路线、日期时间、车型、乘客信息，并备注导盲犬，每一步都语音播报。 | H Agents API（云端浏览器）、进度 → TTS |
| 6 | **确认。** 提交预订前，Voilà 读回接车时间、地址、价格和导盲犬备注。Karim："Oui。" | `confirm_with_user` |
| 7 | **支付交接。** agent 到达商家的银行卡付款页后停下。App 在 Karim 手机上打开该页面并提示："车已为你保留，请现在用 Apple Pay 支付 65 欧。"Karim 双击侧边按钮，用 Face ID 确认。 | `handoff_payment` 自定义工具 → 商家的 Stripe Checkout 在 App 内浏览器打开 |
| 8 | **后续。** Voilà 朗读预订卡片：上车点、时间、订单号、商家电话（一键拨打）。如果商家尚未确认接受导盲犬，Voilà 会如实告知，并继续通过邮件或电话跟进。 | 结构化结果 |

**时间预算。** 国际航班托运通常在起飞前约 60 分钟截止（以航司为准）。北站到 CDG 走公路需要 40–60 分钟以上，B 线停运时会更久。**所以 Voilà 大约只有 10 分钟**，要让 Karim 拿到一个已确认、已付款的预订。

## 3. 背景与问题

- 视障/低视力用户本来就很难使用预订和支付网站：屏幕阅读器要逐个听几百个元素，很多小型出行网站还用自定义控件、没有标签。
- 一旦遇到交通中断，这就变成紧急情况：没时间、环境嘈杂、无人可问、失败代价高（误机）。
- 紧急时真正需要用的网站（本地接送、出租车公司、小运营商）恰恰最不可能做无障碍，也最不可能接入任何插件。商家侧按钮（v0.1）在这里帮不上忙，帮助必须来自**用户侧**。
- Computer-use agent 可以靠"看屏幕"操作任意网站；H 的 Agents API 把它做成了可观测、可中途干预的云服务。

## 4. 定位

- **"你的助手，在任何网站上。"** Voilà 在用户明确要求下，代用户在公开的预订流程中操作，就像一个看得见的朋友帮你拿着手机。
- **我们说"无障碍"，不说"合规"。** Voilà 不修改任何网站，也不让任何网站"合规"，不得作此宣称。
- **控制权在用户手里**：每次预订都要语音确认，**由用户本人付款**，Voilà 不经手卡信息。
- **压力下也要诚实**：哪些已确认、哪些未确认（"商家尚未确认接受导盲犬"）都要说清楚，绝不承诺用户一定赶得上航班。

## 5. 目标与非目标

### 5.1 目标

1. 在嘈杂环境中说一句话，到拿到已确认的预订和手机上的付款提示，**≤ 5 分钟**（目标），并且始终在时间预算内。
2. 行动前实时核实情况（停运、替代方案），只提供仍能赶上截止时间的选项。
3. 在用户看不到屏幕的情况下，完成一个真实世界里不可访问的第三方预订流程。
4. Voilà 和 agent **零接触卡信息**：在用户手机上通过商家自己的付款页支付（可用时走 Apple Pay）。
5. 每个不可逆步骤（提交预订）都必须语音确认。
6. 考虑导盲犬：预订时说明，并如实告知商家是否已接受。

### 5.2 非目标

- 修复第三方网站，或出具合规声明。
- 做收单方或持有资金（MVP 不做钱包、不做虚拟卡）。
- 保证准时到达或保证有车。
- 破解验证码；被挡住时改走下一个方案。
- 黑客松 demo 期间在真实网站上下单（使用仿真站，见 §11）。

## 8. 产品形态与架构

**手机端形态：** 本次黑客松为避免发布 App 的繁琐（应用商店审核、签名、安装），手机端**只做一个移动网页**：用户在手机浏览器（iOS Safari / Android Chrome）打开链接即可使用，无需安装。网页提供全部手机端功能：大按钮、语音进度、数据流、支付交接、预订卡片。原生 App 留到后续版本。

```
手机网页（浏览器打开，无需安装）：大按钮 · 语音进度 · 数据流 · 支付交接 · 预订卡片
        │ 音频流                                  ▲ 付款链接 / 预订卡片
        ▼                                         │
                       Voilà 后端（编排器）
   ┌───────────┬──────────────┬───────────────┬──────────────┬─────────────┐
   ▼           ▼              ▼               ▼              ▼             ▼
 Gladia      IDFM PRIM      Linkup         H Agents API    TTS          用户档案
 嘈杂环境    实时交通       联网搜索        云端浏览器                   （姓名、电话、
 语音转写    （RER B）      （带来源）：    在第三方站                   邮箱、导盲犬、
                            替代方案        完成预订                     语言）
                                              │ 付款前停下
                                              ▼
                              商家自己的付款页（如 Stripe Checkout）
                              在用户手机上打开 → Apple Pay
```

### 8.1 流程

`听 → 理解 → 调研 → 决策 → 执行 → 确认 → 支付交接 → 后续`

每个阶段都有语音播报（静默不超过约 5 秒），同时显示在数据流面板上，方便同行的明眼人查看，也用于 demo 展示。

### 8.2 支付交接：方案对比

| 方案 | 做法 | 结论 |
| - | - | - |
| **A. 交接商家付款链接** | agent 走到商家托管的付款页（真实站点会跳转到 Stripe），后端取出 URL，手机网页在浏览器新标签页中打开（iOS Safari / Android Chrome）。商家开通了 Apple Pay 就用 Apple Pay，否则在该页面填卡。 | **采用。** 卡信息不经过 Voilà；Stripe Checkout 这类托管页不依赖 agent 浏览器的 cookie。 |
| B. 把 agent 实时画面投到手机 | 把云端浏览器画面推流到手机 | 否决：视频流 VoiceOver 读不出来，等于把"盲人杀手"页面原样扔回给盲人。 |
| C. Voilà 作为收单方 | 用户通过 Stripe/Apple Pay 付给 Voilà，Voilà 用一次性虚拟卡（如 Stripe Issuing）付给商家 | 远期方向：体验最顺，但 Voilà 要经手资金（合规、退款、拒付），MVP 不做。 |
| D. 上车付款 | 商家提供现金或上车付款时选择该项 | 只作兜底，不能默认存在。 |

注意：付款链接通常会过期（有效期由商家设定）。真实站点在付款**之前**就已生成订单，用户不付款会留下一个待付款订单，必须告知用户。

优先级：P0 = MVP 必须；P1 = MVP 应有；P2 = 后续版本。

### 9.4 推荐 agent 配置

- 模型 `holo4-27b`，`reasoning_effort: disabled`，`settle_s: 0.3`，视觉模式 1280×800（基线见 §13）。
- 没有商家提供的站点说明，因此由我们为每个已知预订站维护一份内部**站点手册**（字段顺序、控件怪癖、下拉选项全文）。
- `start_url` 直接指向预订表单；`max_steps: 60`；`max_time_s: 240`（限时，见 FR-26）。

## 10. 非功能需求

| 类别 | 要求 |
| - | - |
| 延迟 | 从说话到读出方案 ≤ 30 s；agent 预订 ≤ 3 分钟；从说话到收到付款提示 ≤ 5 分钟（目标） |
| 鲁棒性 | 在车站噪音录音（警报、广播）下转写正确；demo 流程连续成功 3 次 |
| 成本 | 每次协助出行 < €0.30（agent + STT/TTS + 搜索） |
| 安全 | 从不经手卡信息；禁止 agent 付款；每次提交预订都要语音确认 |
| 隐私 | 位置和语音只用于当前任务；截图保留期可配置（`delete_after_min`）；档案尽量存在设备上 |
| 无障碍 | 手机网页符合 WCAG 2.2 AA，并用 VoiceOver 实测 |
| 并发 | 免费版全 org 只有 3 个 H 并发 session；demo 前确认没有残留在运行的 session |

## 11. Demo 设计

**不要在真实站点上提交预订**（会产生真实订单，且它的反爬挑战会让每次运行结果不可预测）。改为：

| 元素 | Demo 做法 |
| - | - |
| 预订网站 | **仿真克隆** paris-airport-shuttle.com 的预订流程，保留它的烂 UI：字段无标签、自定义日期/时间选择器、地址自动补全写入隐藏坐标、多步流程、倒计时后自动跳转付款 |
| 支付 | 仿真站创建开启了 Apple Pay 的 **Stripe Checkout Session（测试模式）**；手机打开托管的 Checkout 页，用 Apple Pay（测试）支付。架构与真实站一致（真实站同样跳转 Stripe） |
| RER B 状态 | 当天能拿到就用 PRIM 实时数据，否则使用录制好的响应，并在数据流中标明 |
| Uber | 不查询：用户已说明叫不到（Linkup 拿不到 Uber 实时等待时间） |
| 替代方案 | 真实 Linkup 搜索 + 预置清单 |
| 噪音 | 用户说话时播放录制的北站警报/广播音轨 |
| 舞台 | 笔记本显示数据流 + agent 实时画面；Apple Pay 环节投屏手机 |

## 12. 成功指标

**产品指标（待验证的假设）**
- 交通中断场景下的协助出行完成率（从请求到已付款的预订）
- 从请求到收到付款提示的耗时
- 上车前导盲犬已获确认的预订比例
- 用户信任度：通过交接完成付款、而不是中途放弃的用户比例

**MVP / Demo 验收**
- 在车站噪音下说一句话 → 正确提取行程。
- 30 s 内朗读出停运原因和 2–3 个可行方案，并附带来源。
- agent 完成仿真站预订流程；**每次**都在提交前调用 `confirm_with_user`、在付款页调用 `handoff_payment`。
- 手机上完成 Apple Pay（测试）支付，预订卡片被朗读出来。
- 全流程 ≤ 5 分钟，连续成功 3 次；剪辑后能放进 3 分钟 pitch。

## 13. 实测基线与真实站点要点

v0.1 在 12 步仿真药房下单上的实测（2026-11-07）：

| 配置 | 耗时 | 步数 | 成本 |
| - | - | - | - |
| holo4-27b, reasoning off, settle 0.3 | 49.7 s | 13 | $0.039 |
| 同上 + 站点说明 + 直达 `start_url` | **40.1 s** | 11 | **$0.030** |
| 同上，本地 runtime | 26.6 s | 12 | $0.041 |
| holo4-35b-a3b, reasoning off | 55.6 s | 17 | $0.032（乱点） |

- `confirm_with_user` 在 4/4 次运行中都在付款前被调用，说明 `handoff_payment` 也有望做到同样可靠。
- 原生 `<select>` 必须给出完整选项文字；接送站表单有很多下拉框（乘客数、行李数、接送类型），要把选项全文写进站点手册。
- 接送站流程比药房更长、更难（地址自动补全、日期/时间选择器），预计 20–40 步，**需在仿真克隆站上实测**。

## 14. 商业模式

- **B2C（已定）**：用户付费，具体定价待验证。
- **B2B2C（后续可选渠道）**：交通运营商、机场、航司、旅行保险或残障协会合作。
- 单位成本：agent 几美分 + STT/TTS/搜索，远低于一次人工协助电话。
- 护城河：本地运营商的站点手册积累 + 交通中断处理逻辑。

## 15. 风险与对策

| 风险 | 对策 |
| - | - |
| 第三方网站条款 / 反爬（真实站首次访问就返回 JS 挑战页） | 用户发起、低频操作；失败就换下一个方案；长期寻求合作 |
| 验证码挡住 agent | 限时；换方案或打电话给商家；绝不尝试破解 |
| 自定义选择器选错日期/时间 | 确认摘要必须包含日期和时间；同时校验结构化结果 |
| 订单已生成但未付款 | 告知用户；付款链接过期前一直可以继续付；用户放弃则取消订单 |
| 商家没开通 Apple Pay | 在商家页面上填卡（仍在用户手机上），或在商家提供时选择上车付款 |
| 上车时导盲犬被拒 | 预订时备注 + 商家明确确认；告知用户确认状态；引用 Loi n°87-588 art. 88 / CASF R241-23（[通行权与拒绝处罚](https://www.service-public.gouv.fr/particuliers/vosdroits/F35787)） |
| agent 抄错付款 URL（长片段） | demo 按预订号从后端查 URL；真实站由 `payment_url` 传入并校验域名，不假设 API 提供当前页面 URL |
| 订到车仍误机 | 绝不承诺；说明时间余量；优先推荐最快方案（北站出租车站） |
| 嘈杂环境识别错误 | 降噪 + Gladia；关键信息（航站楼、时间）要确认；用录音做测试 |
| 延迟导致冷场 | 每个阶段都播报；追问缺失信息的同时并行调研；`start_url` 直达表单 |
| demo 期间产生真实订单 | 只用仿真站；Stripe 测试模式 |
| 并发配额不足 | demo 前确认没有在运行的 H session |

## 17. 已决 / 调研结论

1. 真实站用 Chauffeur Booking System 跳转 Stripe Checkout；card 支付可包含 Apple Pay，但须商家启用，未下真实订单无法确认；Session 默认 24 h，可设 30 min–24 h（[Stripe](https://docs.stripe.com/payments/checkout/managing-limited-inventory)）。
2. 托管 Checkout 无需注册域名或 Apple 开发者账号，Stripe 处理商户验证；Safari + Dashboard 启用 Apple Pay + 测试密钥 + iPhone Wallet 真实卡可测试且不扣款，测试卡不能加入 Wallet（[Stripe](https://docs.stripe.com/apple-pay)）。
3. PRIM 账号 →「Mes jetons d'authentification」→ `apikey` 请求头，默认 5 次/s、1000 次/日；RER B 为 C01743，优先 Messages Info Trafic v2 / Navitia `line_reports`（`line:IDFM:C01743`），备用 `GET /general-message?LineRef=STIF:Line::C01743:`；北站–CDG 由 SNCF 运营，其实时 API 不含 SNCF 媒体发布的信息，必须用 Linkup 交叉核实（[PRIM](https://prim.iledefrance-mobilites.fr/)）。
4. 无公开车站噪音基准，须录音实测；Gladia live v2 用 `pre_processing.audio_enhancer: true`、`speech_threshold: 0.7`（默认 0.6，测试 0.5–0.8）、`custom_vocabulary`（CDG、2E、Gare du Nord、RER B、G7）、法语；客户端先只开浏览器 `noiseSuppression`（[Gladia](https://docs.gladia.io/api-reference/v2/live/init)）。
5. agent 可看地址栏，但 API 文档无后端可读的当前 URL 字段，Stripe 长 `#…` 易抄错；demo 由 `handoff_payment` 传预订号、后端查 Checkout URL，真实站传 `payment_url` 并校验域名（[H Agents API](https://hub.hcompany.ai/agents-api/browser/configuration.md)）。
6. Loi n°87-588 art. 88 保障 CMI 持有者携导盲犬进入交通工具及公共场所且不加价；拒绝按 CASF R241-23 属三级违警，个人最高 €450、法人 €2,250（[Service Public](https://www.service-public.gouv.fr/particuliers/vosdroits/F35787)）；MLD-2013-88 记录巴黎出租车 13/30 拒载；Légifrance 原文抓取受阻，不作逐字引用。
7. **已定：用户付费（B2C）**（[商业模式](#14-商业模式)）。
